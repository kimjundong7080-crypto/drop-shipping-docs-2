드랍쉽핑 API에서 상품 데이터를 가져와 로컬 Python 프로그램으로 가공한 뒤, WooCommerce(WordPress)와 Shopify에 동시에 상품을 등록·관리하는 파이프라인은 충분히 구현 가능합니다. 핵심은 **공급처 API → 데이터 정규화 → 각 판매 채널 API** 순서로 모듈을 분리하는 것입니다.

---

### 전체 아키텍처

```
드랍쉽핑 API (CJ / AliExpress 등)
        │  (상품, 변형, 재고, 가격 조회)
        ▼
┌─────────────────────────────────────┐
│        로컬 Python 프로그램          │
│  ┌─────────┐  ┌──────────────────┐  │
│  │ Fetcher │→│  Normalizer      │  │
│  │ (수집)  │  │ (공통 스키마 변환)│  │
│  └─────────┘  └────────┬─────────┘  │
│                        │            │
│         ┌──────────────┴──────────┐ │
│         ▼                         ▼ │
│  ┌────────────┐           ┌────────────┐│
│  │ WooCommerce│           │  Shopify   ││
│  │  Uploader  │           │  Uploader  ││
│  └────────────┘           └────────────┘│
└─────────────────────────────────────┘
        │                         │
        ▼                         ▼
   WordPress/WooCommerce      Shopify Store
```

이 구조의 장점은 공급처가 바뀌어도 `Fetcher`만 교체하면 되고, 판매 채널이 추가되어도 `Uploader`만 추가하면 된다는 점입니다.

### 1. 드랍쉽핑 API 선택과 상품 수집

#### CJ Dropshipping

CJ는 **API V2.0**을 제공하며, Python 클라이언트(`reedjones/python-cjdropshipping-api`)가 존재하지만 오래되어 일부 엔드포인트만 지원합니다. 실무에서는 `requests`로 직접 호출하는 편이 안정적입니다. CJ API는 OAuth 2.0 인증을 사용하며, 상품 검색·SKU 상세 조회·주문 생성 등의 엔드포인트를 제공합니다.

```python
# cj_fetcher.py (개념 예시)
import requests, os

CJ_BASE = "https://developers.cjdropshipping.com/api2.0/v1"
TOKEN = os.environ["CJ_ACCESS_TOKEN"]

def fetch_products(keyword: str, page: int = 1, size: int = 50) -> list[dict]:
    resp = requests.get(
        f"{CJ_BASE}/product/list",
        headers={"CJ-Access-Token": TOKEN},
        params={"productNameEn": keyword, "pageNum": page, "pageSize": size},
        timeout=30,
    )
    resp.raise_for_status()
    return resp.json().get("data", {}).get("list", [])

def fetch_sku_detail(pid: str) -> dict:
    resp = requests.get(
        f"{CJ_BASE}/product/variant/query",
        headers={"CJ-Access-Token": TOKEN},
        params={"pid": pid},
        timeout=30,
    )
    resp.raise_for_status()
    return resp.json().get("data", {})
```

> CJ는 Shopify·WooCommerce용 **게시(publish) API**도 제공하지만, 직접 각 채널의 API를 호출하는 편이 세밀한 제어가 가능합니다.

#### AliExpress

AliExpress는 공식 Open API보다 **스크래핑·확장 프로그램 기반**으로 상품 데이터를 수집하는 경우가 많습니다. 공식 API를 사용하려면 AliExpress Open Platform 파트너 등록이 필요하며, 승인까지 시간이 걸릴 수 있습니다. 초기에는 CJ Dropshipping으로 시작하고, 필요 시 AliExpress Fetcher를 추가하는 전략이 현실적입니다.

### 2. 공통 상품 스키마(정규화)

공급처마다 필드명이 다르므로, 중간 표현을 하나 정의합니다.

```python
# models.py
from dataclasses import dataclass, field

@dataclass
class Variant:
    sku: str
    price: float
    stock: int
    options: dict[str, str]          # {"Color": "Black", "Size": "M"}
    image: str | None = None

@dataclass
class NormalizedProduct:
    source_id: str                   # 공급처 상품 ID
    title: str
    description_html: str
    images: list[str] = field(default_factory=list)
    variants: list[Variant] = field(default_factory=list)
    tags: list[str] = field(default_factory=list)
    category: str | None = None
```

`Fetcher`는 공급처 응답을 이 `NormalizedProduct`로 변환하고, 이후 `WooCommerceUploader`와 `ShopifyUploader`는 이 정규화된 객체만 받아서 동작하도록 분리합니다.

### 3. WooCommerce(WordPress) 상품 등록

WooCommerce는 공식 Python 래퍼 `woocommerce` 패키지를 제공합니다.

```bash
pip install woocommerce python-dotenv
```

```python
# woocommerce_uploader.py
import os
from woocommerce import API
from models import NormalizedProduct

wcapi = API(
    url=os.environ["WC_STORE_URL"],           # https://your-store.com
    consumer_key=os.environ["WC_CONSUMER_KEY"],
    consumer_secret=os.environ["WC_CONSUMER_SECRET"],
    version="wc/v3",
    timeout=30,
)

def upload_product(product: NormalizedProduct) -> dict:
    payload = {
        "name": product.title,
        "type": "variable" if len(product.variants) > 1 else "simple",
        "description": product.description_html,
        "images": [{"src": url} for url in product.images],
        "categories": [{"name": product.category}] if product.category else [],
        "tags": [{"name": t} for t in product.tags],
    }

    if len(product.variants) > 1:
        payload["attributes"] = _build_attributes(product.variants)
        payload["variations"] = [
            {
                "regular_price": str(v.price),
                "sku": v.sku,
                "manage_stock": True,
                "stock_quantity": v.stock,
                "attributes": [
                    {"name": k, "option": val} for k, val in v.options.items()
                ],
            }
            for v in product.variants
        ]
    else:
        v = product.variants[0]
        payload.update({
            "regular_price": str(v.price),
            "sku": v.sku,
            "manage_stock": True,
            "stock_quantity": v.stock,
        })

    resp = wcapi.post("products", payload)
    resp.raise_for_status()
    return resp.json()


def _build_attributes(variants):
    """variants에서 사용 가능한 속성 목록을 추출"""
    options: dict[str, set] = {}
    for v in variants:
        for k, val in v.options.items():
            options.setdefault(k, set()).add(val)
    return [
        {"name": k, "visible": True, "variation": True, "options": sorted(vals)}
        for k, vals in options.items()
    ]
```

WooCommerce는 **배치 엔드포인트**(`products/batch`)를 제공하므로, 대량 상품은 한 번에 최대 100개까지 묶어서 처리할 수 있습니다. 초기 동기화 시에는 배치를 활용하고, 개별 업데이트는 단건 API를 사용하는 것이 효율적입니다.

**인증 키 발급 경로**: WooCommerce → Settings → Advanced → REST API → Add key (Read/Write 권한).

### 4. Shopify 상품 등록

Shopify는 **REST Admin API**가 점진적으로 폐지되고 **GraphQL Admin API**로 이전하는 추세이므로, 신규 개발은 GraphQL을 권장합니다. 다만 REST가 여전히 동작하며, `requests`로 간단히 구현할 수 있습니다.

#### REST 방식 (간단한 시작용)

```python
# shopify_uploader_rest.py
import os, requests
from models import NormalizedProduct

SHOP = os.environ["SHOPIFY_SHOP"]               # your-store.myshopify.com
TOKEN = os.environ["SHOPIFY_ADMIN_TOKEN"]       # shpat_...
API_VER = "2025-01"

def upload_product(product: NormalizedProduct) -> dict:
    url = f"https://{SHOP}/admin/api/{API_VER}/products.json"
    headers = {"X-Shopify-Access-Token": TOKEN, "Content-Type": "application/json"}

    payload = {
        "product": {
            "title": product.title,
            "body_html": product.description_html,
            "status": "draft",                 # 검토 후 active로 변경
            "images": [{"src": img} for img in product.images],
            "tags": ",".join(product.tags),
            "variants": [
                {
                    "sku": v.sku,
                    "price": str(v.price),
                    "inventory_quantity": v.stock,
                    "inventory_management": "shopify",
                    "option1": list(v.options.values())[0] if v.options else None,
                }
                for v in product.variants
            ],
        }
    }
    if len(product.variants) > 1 and len(product.variants[0].options) > 1:
        payload["product"]["options"] = [
            {"name": k} for k in product.variants[0].options.keys()
        ]

    resp = requests.post(url, json=payload, headers=headers, timeout=30)
    resp.raise_for_status()
    return resp.json()["product"]
```

Shopify의 REST 상품 생성은 `"product"` 키 아래에 데이터를 감싸는 구조입니다. 변형(variant)이 여러 개일 때는 `options` 배열을 함께 정의해야 Shopify가 올바르게 변형을 생성합니다.

#### GraphQL 방식 (권장)

공식 `ShopifyAPI` SDK 또는 `shopify-client`를 사용하면 GraphQL 호출을 더 편하게 관리할 수 있습니다. GraphQL은 한 번의 mutation으로 상품과 변형을 함께 생성할 수 있어 REST보다 왕복 횟수가 적습니다.

```python
# shopify_uploader_graphql.py (개념)
import requests, os, json

def graphql(query: str, variables: dict):
    resp = requests.post(
        f"https://{os.environ['SHOPIFY_SHOP']}/admin/api/2025-01/graphql.json",
        headers={
            "X-Shopify-Access-Token": os.environ["SHOPIFY_ADMIN_TOKEN"],
            "Content-Type": "application/json",
        },
        json={"query": query, "variables": variables},
        timeout=30,
    )
    resp.raise_for_status()
    body = resp.json()
    if "errors" in body:
        raise RuntimeError(body["errors"])
    return body["data"]

PRODUCT_CREATE = """
mutation productCreate($input: ProductInput!) {
  productCreate(input: $input) {
    product { id title }
    userErrors { field message }
  }
}
"""
```

Shopify는 **2025년 이후 GraphQL 중심으로 API 전략이 이동**하고 있으므로, 장기 운영을 고려한다면 GraphQL Uploader를 기본으로 두는 것이 좋습니다.

### 5. 통합 파이프라인

```python
# pipeline.py
from cj_fetcher import fetch_products, fetch_sku_detail
from models import NormalizedProduct, Variant
from woocommerce_uploader import upload_product as wc_upload
from shopify_uploader_rest import upload_product as shopify_upload

def build_normalized(cj_raw: dict, sku_data: dict) -> NormalizedProduct:
    variants = [
        Variant(
            sku=v["variantSku"],
            price=float(v["variantSellPrice"]),
            stock=int(v.get("variantInventory", 0)),
            options=v.get("variantStandard", {}) or {},
            image=v.get("variantImage"),
        )
        for v in sku_data.get("variants", [])
    ]
    return NormalizedProduct(
        source_id=cj_raw["pid"],
        title=cj_raw["productNameEn"],
        description_html=cj_raw.get("description", ""),
        images=[cj_raw.get("productImage")] if cj_raw.get("productImage") else [],
        variants=variants,
        tags=cj_raw.get("tags", []),
        category=cj_raw.get("categoryName"),
    )

def sync_one(cj_product: dict):
    sku_data = fetch_sku_detail(cj_product["pid"])
    normalized = build_normalized(cj_product, sku_data)

    results = {}
    for name, uploader in [("woocommerce", wc_upload), ("shopify", shopify_upload)]:
        try:
            results[name] = uploader(normalized)
            print(f"[OK] {name}: {normalized.title}")
        except Exception as e:
            results[name] = {"error": str(e)}
            print(f"[FAIL] {name}: {normalized.title} → {e}")
    return results

if __name__ == "__main__":
    products = fetch_products("phone case", page=1, size=20)
    for p in products:
        sync_one(p)
```

### 6. 주의사항과 권장 설계

**API 속도 제한(Rate Limit)** 을 반드시 처리해야 합니다. Shopify REST는 초당 2요청(버킷 40), WooCommerce는 호스팅 환경에 따라 다르지만 보수적으로 접근하는 것이 안전합니다. `time.sleep` 또는 `tenacity` 같은 재시도 라이브러리로 지수 백오프를 적용하세요.

**이미지 처리**: 공급처 이미지 URL을 그대로 각 채널에 전달하면 채널이 이미지를 가져오는 과정에서 실패할 수 있습니다. 가능하면 로컬에 다운로드한 뒤 각 채널의 미디어 업로드 API를 사용하는 편이 안정적입니다. WooCommerce는 `products/{id}/images` 엔드포인트, Shopify는 `productCreateMedia` mutation을 사용합니다.

**재고·가격 동기화**는 상품 등록보다 더 자주 발생합니다. 상품 등록은 1회성이지만, 재고/가격은 주기적(예: 1시간마다)으로 공급처 API를 폴링하여 각 채널의 변형 SKU를 기준으로 업데이트하는 별도 잡(Job)으로 분리하는 것이 좋습니다.

**인증 정보 관리**: `consumer_key` / `consumer_secret` / `access_token`은 절대 코드에 하드코딩하지 말고 `.env` 또는 OS 키체인에 보관하세요. `python-dotenv`를 사용하면 로컬 개발과 배포 환경을 쉽게 분리할 수 있습니다.

**초기 동기화는 `draft` 상태로**: Shopify는 `status: "draft"`, WooCommerce는 `status: "draft"`로 먼저 생성한 뒤, 이미지·변형·가격이 정상적으로 매핑되었는지 확인하고 일괄 `publish`하는 워크플로를 권장합니다. 드랍쉽핑은 공급처 데이터 품질이 일정하지 않으므로 검수 단계를 두는 것이 안전합니다.
